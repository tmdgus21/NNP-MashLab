# 조율·추천·투표 규칙

- 기준 문서 `docs/potato-meet/coordination-algorithm.md`(정책 동기화 2026-11-16, 보완 2026-11-17). 다르게 구현하지 않는다.
- `coordination.py`는 순수 함수(DB·HTTP·시계 의존 없음). 현재 시각이 필요하면 인자로 받는다.
- 0/1/2+ 후보 분기는 `service.py`의 한 함수에서만 판단. 앱은 서버 결과를 표시만 한다. **Qwen은 설명만**, 후보·순위·확정은 결정적 서버 코드가 한다.
- **`SLOT_MINUTES=30`**. 모든 구간은 30분 경계 반열린 `[start,end)`, 자정에서 분리, 조율 시각 이전(30분 경계로 올림) 제거. 5분 슬롯 코드 금지.
- **후보**: 2명 이상, 연속 60분 이상. 구간 전체 **교집합**이 가능 인원. 같은 집합의 **최대** 구간만(부분 구간 중복 금지). 집합 변화마다 긴 구간을 자르는 방식 금지(예: AB 10–13 + C 11–12 → AB 3h와 ABC 1h 모두 후보). `max(count)`만 남기고 버리지 않음.
- **추천 순서 `sort_order`**: 가능 인원 DESC → 구간 길이 DESC → 시작 시각 ASC. 표시 순서와 동점 처리에 같은 값을 쓴다.
- 입력은 **비동기 단일 세션**: 24시간 × 30분 격자, 기본값 전부 가능, 안 되는 칸만 표시 후 "완료". 서버에는 최종 '가능' 구간(30분 경계)만. 모임 생성에 길이(duration) 입력 없음.
- **자동 마감·유예**: 전원 완료(≥2)로 **전이**될 때만 `grace_until=now+3분`. 유예 중 재제출은 내용만 저장·**grace 유지**(재연장 금지). 신규 참가로 전원 완료 깨짐 → grace NULL. 다시 전원 완료 → 새 3분. `closes_at`이 더 빠르면 데드라인 우선. 개인 제출만으로 조율 시작 금지. 1명 모임은 전원 완료 마감 없음. 수동 시작 API 금지. `close_collection_if_due` 멱등+행 잠금.
- **마감 시 완료자 판정**: ≥2 → 조율. <2 → 입력 기간당 **연장 1회**(24시간, `rooms.ends_at` 초과 금지, `extended_count ≤ 1`). 연장 후에도 <2 → 조율 불가(cancelled). 입력을 열어 둔 채 무기한 대기하는 경로 금지.
- **참여(join)** 는 입력 OPEN 또는 3분 유예 중에만(Q14). 마감·후보 계산 이후·투표·확정·진행 중·지난 모임·기존 앱 모임(Q13)은 409. 초대만 받은 사람은 인원에 세지 않음. 초대 대기 없음. 새 참여는 `closes_at` 불변.
- **개인정보**: 입력 중에는 칸·힌트 모두 **인원 수만**(남의 불가 격자·개인 선택·닉네임별 가능 여부 미노출). 후보가 나온 뒤에만 후보별 가능한 사람 닉네임. 멤버 목록 닉네임은 표시. 이메일은 어디에도 노출 금지. 재조정 힌트(시간 부족·인원 부족)는 최대 5개, 인원 수 표기.
- 실패 단계: 후보 0개 → 재조정 최대 4회(처음 제외, 같은 날짜 범위의 남은 미래, 이전 답 미리 채움) → 조율 불가(cancelled). 무한 반복 경로가 없어야 한다.
- **날짜 확장 없음**: `rooms.starts_at`/`ends_at`을 바꾸는 코드 금지. 범위는 생성 시 오늘 ~ 오늘+1개월(서버 한국 시각, 달력·말일 보정). 연장도 이 범위를 넘지 않는다.
- 투표 마감 = min(시작+6시간, 가장 이른 후보 시작−30분). 투표 시간 1시간 미만이 되는 후보는 투표 전 제외 후 다시 분기(Q30). 지난 시간을 확정하는 코드 경로가 없어야 한다.
- **투표 자격**: 그 조율의 입력 완료자만(Q33, 아니면 403). 선택 후보는 본인이 가능한 후보만(아니면 422). 투표는 선택 참여, 미투표자는 집계에서 제외될 뿐 진행을 막지 않는다. **빈 투표(후보 0개 선택)는 '투표 완료'**이며 미투표와 구분(`schedule_vote_ballots`). 대상자 전원 완료 시 조기 마감, 아니면 최대 6시간.
- 투표: 다중 선택, 마감 전 재투표 덮어쓰기. 승자 = 최다 득표(plurality) → 동점이면 `sort_order` 최소 → 0표면 1번. 마감 처리는 `close_voting_if_due()` 한 함수, 멱등. **확정 후 불변**(투표·입력·재조정·참여 거부).
- 상수(`MIN_CANDIDATE=60분`, `MIN_PEOPLE=2`, `INPUT_WINDOW=24시간`, `ALL_DONE_GRACE=3분`, `MAX_EXTENSIONS=1`, `VOTING_DURATION=6시간`, `VOTE_LEAD=30분`, `MIN_VOTING=1시간`, `MAX_READJUSTS=4`, `MAX_RANGE=1개월`, `MAX_MEMBERS`=설정값)는 `coordination.py` 상수로만.
- 후보 0개면 재조정(같은 범위), 최대 4회 → 조율 불가. 혼자만 가능한 구간을 후보로 만드는 코드는 어떤 경우에도 금지.
- 삭제(R8): 서버 `require_owner` + 앱 OWNER 전용 노출, 이중 방어. 소프트 삭제(`deleted_at`), 30일 뒤 물리 삭제 정책(배치 미구현일 수 있음). 지난 모임(Q39)=확정 종료 이후. 기존 앱 방(Q13)=조회+방장 삭제만, 자동 변환 금지.
- 문서의 "테스트 필수 케이스"(`test-plan-20261116.md`가 상세 명세, 아직 미실행)는 전부 단위 테스트로 유지.
