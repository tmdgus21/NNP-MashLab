# Potato Meet — 페이지 단위 앱 설명

> 정책 동기화 2026-11-16: 30분 격자, 3분 유예, 연장 1회, 참여 잠금, 후보 정렬, 개인정보 기준을 반영했다. 차이는 `policy-diff-20261116.md` 참고.

허용 범위는 아래 9개 요구사항뿐이다. **R 번호에 연결되지 않는 페이지·기능은 만들지 않는다.**

| R | 요구사항 |
|---|---|
| R1 | 로그인 |
| R2 | 모임 생성 (복수 날짜 선택, 후보일로만 조율) |
| R3 | 모임 공유, 역할: 방장 / 팀원 |
| R4 | 본인 스케줄 입력 (시간 지정) |
| R5 | AI 조율 (날짜 + 시간) |
| R6 | 최다 참여 가능 인원 기준 추천 — ① 가능 요일 ② 가능 시간 |
| R7 | 가능 스케줄 중복 투표 (후보 2개 이상), 1개면 자동 확정 |
| R8 | 모임 삭제는 방장만 가능 |
| R9 | 앱 푸시 알림 — 시작·임박·연장, 종류별 on/off |

## 화면 흐름 — 비동기 단일 세션 + 자동 마감
```
[P1 로그인/회원가입] → [P2 내 모임 목록] ─┬→ [P3 모임 생성] → [P4 모임 상세/공유]
                                          └→ [P4]
초대 링크(https://oranganman.site/join?code=XXXXXXXX) ─→ (로그인) → 참여(입력 중·유예 중에만) → [P4]

[P4] → [P5 내 시간 입력 — 24시간 × 30분 격자 한 화면, 기본 전부 가능, 안 되는 칸만 표시 → 완료]
입력 마감(참가자 전원 완료 → 3분 유예 뒤 / 24시간 도달)
     → 완료자 2명 이상: 서버가 AI 조율 자동 실행
     → 완료자 2명 미만: 24시간 연장 (1회) → 그래도 2명 미만이면 조율 불가
     → [P6 추천 결과] → 후보 1개: 자동 확정 → [P8]
                      → 후보 2개+: [P7 투표 (그 조율의 완료자, 선택, 최대 6시간)] → [P8 확정 결과]
겹치는 시간이 없으면 → 재조정 (같은 날짜 범위의 남은 미래, 내 답 미리 채움, 힌트) → [P5] 다시 (최대 4회) → 조율 불가
```
> 한 사람이 꼭 해야 하는 일은 **입력 1번**. 남을 기다리지 않고, 투표는 선택. 해야 할 때는 푸시 알림(R9)으로 알려준다.
> **개인 제출 ≠ 조율 시작**. 제출만으로는 조율이 시작되지 않고, 수동 "조율 시작" 버튼도 없다.
> 입력 기간은 **24시간 고정**(방장 설정 없음). **ACTIVE 참가자 전원이 입력하면 3분 유예 뒤 자동 마감**(그 사이 고치기·참여 가능, 새 참여로 전원 완료가 깨지면 유예 취소). 초대만 받고 참여하지 않은 사람은 인원에 세지 않으며, 초대 대기 기능은 없다.
> 날짜는 **처음 정한 범위를 넘지 않는다**(종료일 = 데드라인). 범위는 오늘부터 최대 한 달(한국 시간, 실제 달력).
> 개인정보: 입력 중에는 칸별 **인원 수만** 보인다(남의 불가 격자·개인 선택은 안 보임). 후보가 나온 뒤에는 후보별 가능한 사람 **닉네임**을 보여주고, 멤버 목록의 닉네임은 항상 보인다.
> P2(목록)는 R2·R3의 진입점이 되는 최소 연결 화면이다. 검색·정렬·필터 등은 넣지 않는다.

## 공통: 실시간 갱신 (Q10)
- 모임 화면(P4~P8)을 열어 두면 다른 사람의 참여·입력 완료·마감·조율 결과·AI 요약·투표·마감·재조정·삭제가 **새로고침 없이** 반영된다
- 연결이 끊기면 자동 재연결, 앱이 다시 앞으로 오면 최신 상태를 다시 불러온다

## P1. 로그인 (R1)
- 탭 두 개: 로그인 / 회원가입 (`/v1/auth` + 이메일 OTP)
- 입력: 이메일, 비밀번호 (회원가입 시 비밀번호 12자 이상 — 서버 규칙), 이메일로 받은 6자리 OTP
- 가입: 이메일·비밀번호 → OTP 발송 → 검증 성공 시에만 계정 활성화·토큰 발급
- 로그인: 이메일·비밀번호 검증 → OTP 발송 → 검증 성공 시에만 토큰 발급 (기존 세션은 유지)
- 성공 시 Bearer 토큰을 Android Keystore 기반 암호화 저장소에 보관 → P2
- 앱 시작 시 `GET /v1/auth/me`로 토큰 확인. 실패(401)면 P1
- 초대 링크로 들어온 경우 로그인 후 바로 참여 처리 → P4 (참여 불가 상태면 안내만, 아래 P4 참조)

## P2. 내 모임 목록 (R2·R3 진입점)
- 참여 중인 모임 카드: 제목, 날짜 범위, 역할 배지(`방장`/`팀원`), 상태(입력 중/투표 중/확정/조율 불가)
- 확정된 모임의 종료 시각이 지나면 **지난 모임**(상태 표시만, 새 기능 없음) — Potato Meet 확정 일정이 끝난 모임(Q39)
- **기존 조건부 OK 모임**(Q13, 조율 테이블 없음): 목록·상세 **조회 가능**. 배지 예: "이전 앱 모임". 일정 수정·조건 입력·신규 참가·투표·재조율 UI 없음. **방장만 삭제**. 새 스키마로 바꾸거나 숨기지 않음. (지난 모임과 다른 개념)
- "모임 만들기" 버튼 → P3, 카드 → P4, 상단 "초대 코드로 참여" → 8자리 코드 입력 → P4
- 상단 🔔 → **알림 설정 시트**(P9)

## P3. 모임 생성 (R2)
- 입력: 모임 이름(1~100자), 닉네임(1~30자), **복수 날짜 선택**(1개 이상). **모임 시간 길이 입력은 없다** — 후보 = 선택일 안에서 참가자 가능 시간이 겹치는 구간
- 검증: 각 선택일 ≥ 오늘, ≤ 오늘+1개월(실제 달력·말일 보정, 서버 KST). 중복 제거. `selectedDates`와 `startDate`/`endDate` 동시 전송 시 422
- 날짜 선택기는 오늘 이전·한 달 이후를 막는다. **선택하지 않은 날짜**에는 시간 입력·후보가 없다. 이후 단계도 날짜를 늘리지 않는다
- 생성자 = 방장(OWNER). 서버가 8자리 초대 코드 발급 → P4
- 닉네임은 모임 안에서 중복 불가(기존 v21 제약). 참여 시 같은 닉네임이면 "이미 쓰는 닉네임이에요" 안내 후 다시 입력

## P4. 모임 상세 / 공유 (R3, R8)
- 모임 정보(이름, 날짜 범위, 상태), 멤버 목록(닉네임, 역할, 스케줄 입력 ✓ — 닉네임은 항상 표시)
- "초대 링크 공유" → Android 공유 시트 (`https://oranganman.site/join?code=…` + 코드)
- **참여 가능 시점**(Q14·Q20): 입력 중(OPEN) 또는 3분 유예 중에만. **입력 마감·후보 계산 시작 이후·투표·확정·진행 중·지난 모임·기존 앱 모임**에서는 신규 참가 불가 → "지금은 참여할 수 없어요" (**서버 409**). 초대 링크만 보낸 사람은 참가자로 세지 않음
- 진행 표시: 현재 단계(입력 중 / 투표 중 / 확정 / 조율 불가), 재조정 횟수(n/4), "입력 완료 k / N명", **입력 마감까지 남은 시간**
- "내 시간 입력하기" → P5 (완료했으면 "내 입력 고치기"). 마감되면 서버가 자동으로 조율 (**수동 실행 버튼 없음**). 기존 앱 모임에는 입력/투표 진입 없음
- 전원 입력 후 유예 중이면 "모두 입력했어요. 3분 뒤 마감 (그 전에 고치거나 참여할 수 있어요)". 유예 중 고치기는 **마감 시각을 다시 늘리지 않음**
- **방장에게만** "모임 삭제" → 확인 다이얼로그 → 삭제 후 P2 (소프트 삭제 `deleted_at`, 삭제 요청 30일 뒤 물리 삭제 정책 — 정리 배치는 아직 미구현일 수 있음). 기존 앱 모임도 동일(방장만 삭제)
- 서버도 방장이 아니면 403 (UI 숨김만으로 끝내지 않음)

## P5. 내 시간 입력 — 24시간 × 30분 격자 (R4)
- 한 번 들어와서 끝까지: **Etta 스타일 격자**. 날짜 열 × 00:00~24:00 **30분 칸**(하루 48칸), 가로·세로 스크롤, 드래그로 칸 선택
- **처음엔 전부 '가능'**, 안 되는 칸만 '불가'로 표시한다(드래그 시작 칸의 상태로 일괄 전환). 지난 시간·모임 범위 밖은 비활성
- 중간 상태는 기기에 임시 저장(앱을 닫아도 이어서 가능). "완료"를 눌러야 제출, 마감 전까지는 다시 들어와 고칠 수 있음
- 상단: "입력 마감까지 HH:MM 남음"
- 칸 색 농도 = 그 칸에 가능하다고 낸 **인원 수**(제출한 사람 기준). **누가 되는지·남의 불가 격자는 보이지 않는다**
- (이전 3단계 날짜→1시간→5분 다듬기 흐름은 30분 격자로 **대체**되어 폐기)

### 재조정과 힌트 (처음 조율에 실패한 뒤, 최대 4회)
- 같은 날짜 범위의 **남은 미래**로 다시 입력. **내 이전 답이 미리 채워져** 있어 늘리기만 하면 됨
- 안내 "겹치는 시간이 없어요. 아래 구간을 조금만 늘리면 조율할 수 있어요 (재조정 n/4회)"
- **조금만 늘리면 되는 구간** 카드(최대 5개, 실시간 갱신, **인원 수만 표시**):
  - "11/15 19:00–19:30 2명이 겹쳐요. 30분만 더 되면 후보가 돼요"
  - "11/22 14:00–16:00 1명만 돼요. 한 명만 더 되면 후보가 돼요 · **내가** 되면 후보가 돼요"
  - 카드를 누르면 해당 날짜·시간 칸으로 이동
- 재조정 4회 후에도 없거나 범위에 남은 미래 시간이 1시간 미만이면 **조율 불가**: "조율할 수 있는 시간이 없어요", 방장은 모임 삭제 가능

## P6. AI 조율 · 추천 결과 (R5, R6)
- **자동 실행**: 입력 마감(전원 완료 후 3분 유예가 끝났을 때, 또는 마감 시각) 때 서버가 실행한다. 마감 때 미완료자는 이번 조율에서 빠지고 결과만 본다
- 완료자 2명 미만이면 조율하지 않는다: 처음 한 번은 24시간 연장(범위를 넘지 않음), 연장 뒤에도 2명 미만이면 **조율 불가**(열어 둔 채로 두지 않음). 참가자 1명뿐인 모임은 전원 완료만으로 마감하지 않음("팀원을 초대해 주세요")
- 서버가 결정적 코드로 후보를 만든다: **2명 이상이 연속 60분 이상 가능한 모든 구간**을 먼저 찾고, **가능 인원 많은 순 → 구간 긴 순 → 시작 빠른 순**으로 정렬. 최다 인원 구간만 남기고 인원이 적은 유효 구간을 버리지 않는다
- Qwen은 후보를 1~2문장으로 **설명만** 한다(실패하면 요약 없이 표시). 후보·순위·확정은 서버가 정한다
- 표시: "최다 참여 가능 M / 전체 N명", ① 가능 요일 목록, ② 날짜별 가능 시간 구간(추천 순서대로 1, 2, 3…, 각 후보의 **가능한 사람 닉네임**), AI 요약
- AI 요약은 늦게 도착할 수 있다 → 도착 전엔 "요약 준비 중", 실패하면 숨김
- 후보는 **1시간 이상** 구간만, 경계는 30분, 지난 시간은 제외
- 분기:
  - 후보 0개(2명 이상 겹치는 1시간 이상 구간 없음) → **재조정**(같은 날짜 범위, 최대 4회) → P5. 날짜는 늘리지 않음
  - 혼자만 가능한 시간은 절대 후보가 되지 않음
  - 1개 → 자동 확정 → P8
  - 2개 이상 → 투표 시작 → P7

## P7. 중복 투표 (R7)
- 후보 카드(추천 순서 번호, 날짜·요일·시간, 가능한 사람 닉네임) + 체크박스(여러 개 선택) + "투표하기"
- **투표는 선택**: 안 해도 마감 때 자동으로 정해짐. **아무것도 고르지 않고 제출(빈 투표)** 해도 "투표 완료"로 센다(표는 0)
- **내가 참석 가능한 후보만 선택할 수 있다**(그 후보의 가능 멤버에 내가 있어야 함). 아니면 서버가 거절
- 투표 시간은 최대 6시간. 곧 시작하는 후보가 있으면 **그 후보 시작 30분 전**에 마감 (더 짧을 수 있음)
- 투표 시간이 1시간도 안 남는 후보는 투표 전에 빠지고, "곧 시작해서 투표 시간이 부족한 후보 n개는 제외했어요" 표시
- 상단: 남은 시간(마감 시각까지), "투표 완료 k / N명" (N = 이번 조율의 입력 완료자)
- **투표는 그 조율의 입력 완료자만**. 입력하지 않았거나 나중에 들어온 사람은 후보·득표만 봄
- 재투표는 덮어쓰기(마감 전까지). 득표 **수**를 표시하고 투표한 사람 닉네임은 표시하지 않는다
- 마감: 마감 시각(최대 6시간, 가장 이른 후보 시작 30분 전) 도달 **또는** 투표 대상자(입력 완료자) 전원 투표(빈 투표 포함) 시 조기 마감
- 확정: 최다 득표(plurality) 후보. 동점이면 추천 순서(`sort_order`)가 앞선 후보 (아무도 투표하지 않았으면 1번)

## P8. 확정 결과 (R7)
- 확정 날짜·요일·시간, 참여 가능 멤버(닉네임), 확정 방식(자동 확정 / 투표: 전원 투표 완료 / 투표: 마감 시각 도달), 동점으로 정해졌으면 그 사실 표시
- **확정은 되돌릴 수 없다**(불변). 확정 후 스케줄 입력·투표·참여 불가
- 확정된 종료 시각이 지나면 **지난 모임**

## P9. 알림 설정 시트 (R9)
- P2 상단 🔔에서 여는 하단 시트(별도 화면 아님). 계정 단위 설정, 모든 모임에 적용
- 스위치 3개 (기본 모두 켜짐):
  - **시작 알림**: 처음 입력 기간 시작, 투표 시작
  - **임박 알림**: 입력 마감·투표 마감 1시간 전, 아직 안 한 경우만
  - **연장 알림**: 재조정 시작, 입력 기간 하루 연장(1회), 조율 불가(최종 1회)
- Android 13 이상: 처음 모임을 만들거나 참여할 때 알림 권한 요청. 거부하면 시트에 "기기 설정에서 알림 허용" 안내
- 알림을 누르면 해당 모임 화면(P4/P5/P7)으로 이동

### 알림 문구
| 종류 | 상황 | 문구 예시 |
|---|---|---|
| 시작 | 입력 기간 시작 | "[모임명] 가능한 시간을 입력해 주세요 (24시간)" |
| 시작 | 투표 시작 | "[모임명] 후보가 n개예요. HH:MM까지 투표해 주세요 (선택)" |
| 임박 | 입력 마감 1시간 전 | "[모임명] 입력 마감 1시간 전이에요" |
| 임박 | 투표 마감 1시간 전 | "[모임명] 투표 마감 1시간 전이에요" |
| 연장 | 재조정 시작 | "[모임명] 겹치는 시간이 없어요. 조금만 늘리면 조율할 수 있어요 (재조정 n/4회)" |
| 연장 | 하루 연장 (1회만) | "[모임명] 입력한 사람이 2명 미만이라 하루 더 연장합니다" |
| 연장 | 조율 불가 (최종 1회만) | "[모임명] 조율할 수 있는 시간이 없어요. 방장이 모임을 정리할 수 있어요" |
